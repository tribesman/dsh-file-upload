# @dsh-plugins/file-upload

**แถวคลิปหนีบกระดาษใต้หัวข้องานอัตโนมัติ** ในแถบด้านข้างของเว็บ
[DSH](https://github.com/deepseek-ai/deepseek-harness) โดยแถวนั้นเปิดหน้าอัปโหลด: เลือก
โฟลเดอร์บนโฮสต์แบบเดียวกับที่ไดอะล็อกเวิร์กสเปซทำ เลือกหลายไฟล์พร้อมกัน แล้วดู
แต่ละไฟล์อัปโหลดด้วยแถบความคืบหน้าของตัวเอง

## ทำไม

DSH ย้ายไบต์ *ออก* จากเวิร์กสเปซได้แล้ว ([`@dsh-plugins/file-download`](https://github.com/tribesman/dsh-file-download))
และเตรียมไฟล์แนบจากเบราว์เซอร์สำหรับพรอมต์หนึ่งรายการได้ แต่ยังไม่มีทางวางไฟล์ที่
มีอยู่แล้วหลายไฟล์ลงในโฟลเดอร์บนเซิร์ฟเวอร์โดยไม่ต้องมีเชลล์บนโฮสต์ ปลั๊กอินนี้เพิ่ม
ความสามารถนั้นเข้าไป ในตำแหน่งเดียวกับที่แผงระดับโกลบอลอื่น ๆ อยู่

## ปรากฏที่ไหน

| ตำแหน่ง | สิ่งที่แสดง |
| --- | --- |
| แถบด้านข้างซ้าย | แถว **อัปโหลดไฟล์** พร้อมไอคอนคลิปหนีบกระดาษ อยู่ใต้ **งานอัตโนมัติ** พอดี (`order: 11`) |
| คอลัมน์หลัก | หน้าอัปโหลด ซึ่งเปิดขึ้นเมื่อเลือกแถวนั้น |

<img src="../assets/upload-page.png" alt="หน้าอัปโหลดไฟล์ที่ยังไม่ได้เลือกปลายทาง: แถวในแถบด้านข้างอยู่ใต้งานอัตโนมัติ หน้าแสดงการ์ดปลายทางและพื้นที่วางไฟล์แบบเส้นประ" width="1200" />

ทุกอย่างในหน้านี้คือขั้นตอนเดียวที่ต่อเนื่องกัน:

1. **โฟลเดอร์ปลายทาง** — *เลือกโฟลเดอร์* เปิดไดอะล็อกในแอปซึ่งขับเคลื่อนด้วย
   รายการไดเรกทอรีของโฮสต์เอง (`ctx.uiWorkspace.listDirectory` ซึ่งเป็นพื้นฐาน
   ตัวเดียวกับที่อยู่เบื้องหลัง **เลือกไดเรกทอรีเวิร์กสเปซ**): กระโดดผ่านแถบ
   breadcrumb, เส้นทางที่คลิกแก้ไขได้, สวิตช์แสดงโฟลเดอร์ที่ซ่อนอยู่ และการยืนยัน
   *เลือกโฟลเดอร์นี้* ส่วนรายการโฟลเดอร์มาจากโฮสต์ จึงใช้ได้จากเบราว์เซอร์ระยะไกลที่
   ไม่มีตัวเลือกไฟล์ของระบบปฏิบัติการ

   <img src="../assets/folder-picker.png" alt="ไดอะล็อกเลือกโฟลเดอร์บนเซิร์ฟเวอร์: breadcrumb แสดง Home และโฟลเดอร์ demo โดยมี archive, photos และ reports อยู่ในรายการ" width="1200" />

2. **เลือกไฟล์** — ตัวเลือกไฟล์ของหน้ารับหลายไฟล์พร้อมกัน และไฟล์ที่ลากมาวางที่ใดก็ได้
   บนหน้าจะเข้าร่วมคิวเดียวกัน
3. **อัปโหลดไฟล์** — คิวทำงานทีละไฟล์ แต่ละแถวแสดงตัวนับไบต์ที่ส่งไปแล้ว แถบความ
   คืบหน้า และป้ายสถานะ แถวที่ล้มเหลวจะเก็บข้อความไว้และมีปุ่ม **ลองใหม่**;
   **ยกเลิกการอัปโหลด** หยุดคิวและปล่อยให้แถวที่เหลือพร้อมอยู่

   <img src="../assets/uploading.png" alt="การอัปโหลดที่กำลังดำเนินอยู่: แถวแรกแสดง 215 MB จาก 800 MB พร้อมแถบที่เต็มครึ่งหนึ่งและป้ายกำลังอัปโหลด แถวอื่นรออยู่ในสถานะพร้อม และส่วนหัวมีปุ่มยกเลิกการอัปโหลด" width="1200" />

## ทำงานอย่างไร

**ฝั่งโฮสต์** — เส้นทางสตรีมมิ่งที่ผ่านการยืนยันตัวตนบนขอบเขต `/api` ที่ใช้ร่วมกัน:

```
POST /api/file-upload/write?dir=<absolute folder>&name=<file name>
content-type: application/octet-stream
```

เส้นทางนี้อยู่บน `ctx.connection.fetch` ดังนั้น Connection จึงอนุมัติคำขอโดยเทียบกับ
ข้อมูลรับรอง Harness ที่เซ็นแล้วของเบราว์เซอร์ก่อนที่ตัวจัดการนี้จะทำงาน: คำขอที่ยัง
ไม่ได้ยืนยันตัวตนจะไปไม่ถึงตัวจัดการเลย และมีเพียง Peer เจ้าของเท่านั้นที่ได้รับ
บริการ ค่าทั้งสองถูกตรวจสอบ (ไดเรกทอรีแบบสัมบูรณ์ที่มีอยู่จริง; ชื่อไฟล์ล้วนที่ไม่มี
ตัวคั่น) และเนื้อหาจะถูกสตรีมตรงเข้าไฟล์ `.dsh-upload-<uuid>.part` ที่อยู่ข้าง ๆ ซึ่ง
จะถูกเปลี่ยนชื่อเข้าที่ก็ต่อเมื่อไบต์สุดท้ายมาถึงแล้ว — การอัปโหลดที่ถูกยกเลิกหรือล้ม
เหลวจะไม่ทิ้งอะไรไว้ใต้ชื่อจริงเลย

**ฝั่งเบราว์เซอร์** — bundle แบบ lazy-CJS ที่เขียนขึ้นเอง ซึ่งเรียกใช้เฉพาะพื้นฐานที่
shell เตรียมไว้ให้เท่านั้น (`react`, `react-dom`) มันลงทะเบียนสองส่วน: แถว
`sidebar.panellist` และแผง `main` ที่ใช้คีย์เดียวกัน ซึ่งเป็นสัญญาทั้งหมดที่แถบด้านข้าง
ต้องใช้เพื่อเลือกมัน `XMLHttpRequest` ธรรมดาบนเธรดของหน้านี่เองที่ทำให้ความคืบหน้า
รายไฟล์เป็นของจริง: `xhr.upload.onprogress` รายงานไบต์ที่เบราว์เซอร์ส่งเข้าซ็อกเก็ต
ไปแล้วจริง ๆ

## การติดตั้ง

แพ็กเกจนี้เป็น **bundle** (`dsh.bundle.patch`) ดังนั้น Plugin Manager จึงติดตั้งและ
อัปเดตมันเป็นแถวเดียวได้:

```bash
# จากเครื่อง checkout — ลิงก์ไดเรกทอรีนี้ การแก้ไขมีผลทันที
dsh plugin --profile web add /path/to/dsh-file-upload

# หรือจาก git remote
dsh plugin --profile web add "git+https://github.com/tribesman/dsh-file-upload.git"
```

ทั้งสองวิธีทำจาก UI ได้เช่นกัน: **ปลั๊กอิน → เพิ่มปลั๊กอิน**

ถ้าไม่มี `dsh` อยู่บน `PATH` ให้สร้างซิมลิงก์ของ checkout ไว้ในโปรไฟล์แล้วเพิ่มแถวด้วยมือ:

```yaml
# $DSH_HOME/profiles/web/cordis.patch.yml
- insert:
    - id: file-upload-panel
      name: '@dsh-plugins/file-upload'
```

```bash
ln -s /path/to/dsh-file-upload \
  "$DSH_HOME/profiles/web/node_modules/@dsh-plugins/file-upload"
```

รหัสของแถวต้องไม่ซ้ำกับรหัสที่มีมาให้แล้ว: `file-upload` เป็นของ
`@deepseek-ai/dsh-client-file-upload` ซึ่งเป็นช่องทางส่งไฟล์แนบของพรอมต์ในเบราว์เซอร์
อยู่แล้ว และรายการ Loader สองรายการที่ใช้รหัสร่วมกันจะประกอบได้เพียงรายการเดียว
เท่านั้น จึงต้องใช้ `file-upload-panel`

รีสตาร์ตฮาร์เนสหนึ่งครั้งเพื่อให้แถว Loader ที่เพิ่งเพิ่มเข้ามาถูกประกอบ บนอินสแตนซ์
ที่กำลังทำงานอยู่ แถวที่ถูกแทรกจะเมานต์โดยไม่ต้องรีสตาร์ต

ตรวจสอบว่ามันทำงาน: แถบด้านข้างจะมี **อัปโหลดไฟล์** เพิ่มขึ้นใต้ **งานอัตโนมัติ**
พอดี หน้าจะแสดงรายการโฟลเดอร์โฮมของโฮสต์ และการอัปโหลดที่เสร็จแล้วจะไปอยู่ในโฟลเดอร์
ที่คุณเลือก:

```bash
ls -l "/the/folder/you/chose"
```

## การตั้งค่า

พารามิเตอร์ทั้งสองอยู่ในการตั้งค่า `config` ของแถวปลั๊กอิน ชั้นแพตช์ของโปรไฟล์จึงเก็บค่า
เหล่านี้ไว้ได้ข้ามการอัปเกรด:

```yaml
- id: file-upload-panel
  name: '@dsh-plugins/file-upload'
  config:
    maxFileBytes: 1048576      # ค่าเริ่มต้น 1073741824 (1 GiB), 1024 … 16 GiB
    conflict: overwrite        # ค่าเริ่มต้น "rename"
```

| ฟิลด์ | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| `maxFileBytes` | `1073741824` | เพดานสูงสุดแบบรวมค่าขอบสำหรับไฟล์เดียว เนื้อหาที่ใหญ่กว่านี้จะถูกปฏิเสธด้วย `413` และไม่มีอะไรถูกจัดเก็บ |
| `conflict` | `"rename"` | ความหมายเมื่อชื่อถูกใช้ไปแล้ว: `rename` เก็บไฟล์เดิมไว้และวางไฟล์ใหม่เป็น `name (1).ext`; `overwrite` แทนที่ไฟล์เดิม |

แถวนี้ประกาศสคีมาของตัวเองเป็น Standard Schema ที่เขียนขึ้นเอง ค่าข้างต้นจึงถูกตรวจสอบ
ตอนปลั๊กอินเปิดใช้งาน และค่าที่ผิดจะทำให้แถวนั้นล้มเหลวพร้อมข้อผิดพลาด Plugin Manager
อ่านได้เฉพาะกราฟ Schemastery แบบเนทีฟเท่านั้น ฟอร์มการตั้งค่าของมันจึงรายงานว่าสคีมา
ของแถวนี้ไม่รองรับและไม่แสดงฟิลด์ใด ๆ: ให้ตั้งค่าในแพตช์ตามที่แสดงไว้ข้างต้น

## หมายเหตุด้านความปลอดภัย

- เส้นทางนี้เป็น **เส้นทางที่ตรงตัวบนขอบเขต Connection `/api`** ไม่ใช่พาธของเว็บเซิร์ฟเวอร์
  ดิบ ๆ จึงต้องใช้คุกกี้เซสชันที่เซ็นแล้วของเบราว์เซอร์ และให้บริการเฉพาะ Peer เจ้าของ
  เท่านั้น ทั้งยังไม่เพิ่มการผ่อนปรน Host/Origin ใด ๆ ด้วยตัวเอง
- เส้นทางนี้เขียนไปยังที่ใดก็ตามที่ผู้ปฏิบัติงานที่ยืนยันตัวตนแล้วชี้ไป โดยใช้สิทธิ์ของ
  โปรเซส DSH — ขอบเขตเดียวกับที่ตัวเลือกไดเรกทอรีเวิร์กสเปซและเครื่องมือ `bash` มีอยู่แล้ว
  ปลายทางต้องมีอยู่ก่อน ปลั๊กอินไม่สร้างโฟลเดอร์ให้
- เบราว์เซอร์ระบุโฟลเดอร์หนึ่งและชื่อไฟล์หนึ่ง ไม่เคยระบุพาธภายในโฟลเดอร์นั้น: ชื่อต้อง
  ไม่มี `.` และไม่มีตัวคั่น คำขอจึงหลุดออกจากโฟลเดอร์ที่เลือกไม่ได้
- ไฟล์ชั่วคราวถูกสร้างข้าง ๆ เป้าหมายและถูกลบเมื่อล้มเหลวหรือถูกยกเลิก ไม่มีอะไรเหลืออยู่
  ใต้ชื่อสุดท้าย เว้นแต่ทุกไบต์จะมาถึงแล้ว

## ข้อจำกัดที่ทราบ

- คิวอัปโหลดหนึ่งคิวต่อการเข้าชมหนึ่งครั้ง: รายการเป็นข้อมูลเฉพาะหน้านั้น และการออกจาก
  หน้าระหว่างการอัปโหลดจะปล่อยให้การถ่ายโอนดำเนินต่อไป (โฮสต์เขียนไฟล์จนเสร็จ) แต่ลืม
  แถวเหล่านั้นไป
- ตัวเลือกไม่มีฟังก์ชันสร้างโฟลเดอร์และไม่มีการอัปโหลดต่อ: การอัปโหลดที่ล้มเหลวจะเริ่ม
  ใหม่ตั้งแต่ไบต์แรก
- ตัวเลือกแสดงเฉพาะโฟลเดอร์ และระดับที่ถูกตัดจะรายงาน `truncated` แทนการแบ่งหน้า
- หน้าไม่มีขั้นตอนตรวจสอบล่วงหน้าฝั่งไคลเอนต์สำหรับ `maxFileBytes`: ไฟล์ที่ใหญ่เกินจะถูก
  โฮสต์ปฏิเสธหลังจากการถ่ายโอน
- โฮสต์เขียนข้อความแสดงข้อผิดพลาดเป็นภาษาอังกฤษและเก็บรหัส errno ไว้ในข้อความ

## การพัฒนา

```bash
npm test        # node --test: 22 เคสสำหรับเส้นทางและ bundle
npm run check   # ด่านตรวจไวยากรณ์ของทั้งสองฝั่ง
```

เทสต์ฝั่งโฮสต์ขับเส้นทางผ่านออบเจกต์ `Request`/`Response` จริงและไดเรกทอรีชั่วคราวจริง
จึงครอบคลุมเส้นทางการเคลื่อนย้ายไบต์ นโยบายการชนกันของชื่อ เพดานขนาด การยกเลิก และ
ข้อความแจ้งความล้มเหลว โดยไม่ต้องใช้ฮาร์เนส ส่วนเทสต์ฝั่งเบราว์เซอร์รัน bundle ใน VM
ที่มี React และ DOM จำลอง จึงไม่ต้องใช้ทั้งฮาร์เนสและเบราว์เซอร์

## ไฟล์

| เส้นทาง | บทบาท |
| --- | --- |
| `lib/index.js` | ฝั่งโฮสต์: เส้นทางเขียนแบบสตรีมมิ่งและสคีมาการตั้งค่าของมัน |
