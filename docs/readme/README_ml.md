# @dsh-plugins/file-upload

**ഓട്ടോമേഷൻ ടാസ്കുകൾക്കു താഴെയുള്ള ഒരു പേപ്പർക്ലിപ്പ് വരി** [DSH](https://github.com/deepseek-ai/deepseek-harness)
വെബ് സൈഡ്‌ബാറിൽ ഒരു അപ്‌ലോഡ് പേജ് തുറക്കുന്നു: വർക്ക്സ്പേസ് ഡയലോഗ്
ചെയ്യുന്നതുപോലെ തന്നെ ഹോസ്റ്റിലെ ഒരു ഫോൾഡർ തിരഞ്ഞെടുക്കുക, ഒരുമിച്ച്
നിരവധി ഫയലുകൾ തിരഞ്ഞെടുക്കുക, ഓരോ ഫയലും അതിന്റേതായ പുരോഗതി ബാറുമായി
അപ്‌ലോഡ് ചെയ്യുന്നത് കാണുക.

## എന്തുകൊണ്ട്

DSH-ക്ക് ബൈറ്റുകൾ വർക്ക്സ്പേസിൽ നിന്ന് *പുറത്തേക്ക്* കൊണ്ടുപോകാൻ കഴിയും
([`@dsh-plugins/file-download`](https://github.com/tribesman/dsh-file-download)),
ഒരു പ്രോംപ്റ്റിനുവേണ്ടി ബ്രൗസർ അറ്റാച്ച്മെന്റുകൾ സ്റ്റേജ് ചെയ്യാനും
കഴിയും. എന്നാൽ ഹോസ്റ്റിൽ ഒരു ഷെൽ ഇല്ലാതെ നിലവിലുള്ള നിരവധി ഫയലുകൾ
സർവറിലെ ഒരു ഫോൾഡറിലേക്ക് ഇടാൻ ഒരു വഴിയും ഉണ്ടായിരുന്നില്ല. ഈ പ്ലഗിൻ
ഇല്ലാതിരുന്ന ആ ഭാഗം ചേർക്കുന്നു — മറ്റ് ഗ്ലോബൽ പാനലുകൾ നിൽക്കുന്ന അതേ സ്ഥാനത്തു
തന്നെ.

## ഇത് എവിടെ പ്രത്യക്ഷപ്പെടുന്നു

| സ്ഥാനം | എന്ത് |
| --- | --- |
| ഇടത് സൈഡ്‌ബാർ | പേപ്പർക്ലിപ്പ് ഐക്കണോടുകൂടിയ **ഫയൽ അപ്‌ലോഡ് ചെയ്യുക** എന്ന വരി, **ഓട്ടോമേഷൻ ടാസ്കുകൾക്കു** നേരെ താഴെ (`order: 11`) |
| പ്രധാന നിര | ആ വരി തിരഞ്ഞെടുക്കുമ്പോൾ തുറക്കുന്ന അപ്‌ലോഡ് പേജ് |

<img src="../assets/upload-page.png" alt="ഇനിയും ലക്ഷ്യസ്ഥാനം തിരഞ്ഞെടുക്കാത്ത ഫയൽ അപ്‌ലോഡ് ചെയ്യുക പേജ്: സൈഡ്‌ബാർ വരി ഓട്ടോമേഷൻ ടാസ്കുകൾക്കു താഴെയാണ്, പേജിൽ ഒരു ലക്ഷ്യ കാർഡും വരകളുള്ള ഒരു ഡ്രോപ്പ് മേഖലയും കാണാം" width="1200" />

പേജിലെ എല്ലാം ഒരൊറ്റ പ്രവാഹമാണ്:

1. **ലക്ഷ്യ ഫോൾഡർ** — *ഫോൾഡർ തിരഞ്ഞെടുക്കുക* എന്നത് ഹോസ്റ്റിന്റെ
   സ്വന്തം ഡയറക്ടറി ലിസ്റ്റിംഗ് ഉപയോഗിക്കുന്ന ഒരു ഇൻ-ആപ്പ് ഡയലോഗ്
   തുറക്കുന്നു (`ctx.uiWorkspace.listDirectory`, **വർക്ക്സ്പേസ് ഡയറക്ടറി
   തിരഞ്ഞെടുക്കുക** എന്നതിനു പിന്നിലുള്ള അതേ പ്രിമിറ്റീവ്):
   ബ്രെഡ്ക്രംബിലൂടെയുള്ള നീക്കങ്ങൾ, ക്ലിക്ക് ചെയ്ത് തിരുത്താവുന്ന പാത, മറഞ്ഞിരിക്കുന്ന
   ഫോൾഡറുകൾ കാണിക്കാനുള്ള ടോഗിൾ, ഒപ്പം *ഈ ഫോൾഡർ തിരഞ്ഞെടുക്കുക* എന്ന
   സ്ഥിരീകരണം. ഫോൾഡർ ലിസ്റ്റ് ഹോസ്റ്റിൽ നിന്നാണ് വരുന്നത്, അതിനാൽ
   ഓപ്പറേറ്റിംഗ് സിസ്റ്റത്തിന്റെ ഫയൽ ചൂസർ ഇല്ലാത്ത ഒരു റിമോട്ട്
   ബ്രൗസറിൽ നിന്നും ഇത് പ്രവർത്തിക്കുന്നു.

   <img src="../assets/folder-picker.png" alt="സെർവറിലെ ഫോൾഡർ തിരഞ്ഞെടുക്കുക ഡയലോഗ്: ബ്രെഡ്ക്രംബിൽ Home-ഉം demo ഫോൾഡറും കാണാം, archive, photos, reports എന്നിവ ലിസ്റ്റ് ചെയ്തിരിക്കുന്നു" width="1200" />

2. **ഫയലുകൾ തിരഞ്ഞെടുക്കുക** — പേജിന്റെ ഫയൽ പിക്കർ ഒരുമിച്ച് നിരവധി
   ഫയലുകൾ സ്വീകരിക്കുന്നു; പേജിൽ എവിടെയെങ്കിലും ഡ്രോപ്പ് ചെയ്യുന്ന
   ഫയലുകളും അതേ ക്യൂവിൽ ചേരുന്നു.
3. **ഫയലുകൾ അപ്‌ലോഡ് ചെയ്യുക** — ക്യൂ ഒരു സമയം ഒരു ഫയൽ എന്ന രീതിയിൽ
   പ്രവർത്തിക്കുന്നു; ഓരോ വരിയും അയച്ച ബൈറ്റുകളുടെ കൗണ്ടർ, ഒരു പുരോഗതി
   ബാർ, ഒരു സ്റ്റേറ്റ് ടാഗ് എന്നിവ കാണിക്കുന്നു. പരാജയപ്പെട്ട വരി അതിന്റെ
   സന്ദേശം നിലനിർത്തുകയും **വീണ്ടും ശ്രമിക്കുക** നൽകുകയും ചെയ്യുന്നു;
   **അപ്‌ലോഡ് റദ്ദാക്കുക** ക്യൂ നിർത്തുകയും ബാക്കിയുള്ള വരികൾ തയ്യാറായി
   നിലനിർത്തുകയും ചെയ്യുന്നു.

   <img src="../assets/uploading.png" alt="നടന്നുകൊണ്ടിരിക്കുന്ന ഒരു അപ്‌ലോഡ്: ആദ്യ വരി 800 MB-യിൽ 215 MB എന്നും പകുതി നിറഞ്ഞ ബാറും അപ്‌ലോഡ് ചെയ്യുന്നു എന്ന ടാഗും കാണിക്കുന്നു, മറ്റ് വരികൾ തയ്യാർ എന്ന നിലയിൽ കാത്തിരിക്കുന്നു, ഹെഡറിൽ അപ്‌ലോഡ് റദ്ദാക്കുക എന്നതുമുണ്ട്" width="1200" />

## ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു

**ഹോസ്റ്റ് ഭാഗം** — പങ്കിട്ട `/api` അതിർത്തിയിൽ ഒരു ഓതന്റിക്കേറ്റഡ്
സ്ട്രീമിംഗ് റൂട്ട്:

```
POST /api/file-upload/write?dir=<absolute folder>&name=<file name>
content-type: application/octet-stream
```

ഇത് `ctx.connection.fetch`-ൽ ആണ് സ്ഥിതി ചെയ്യുന്നത്, അതിനാൽ ഈ ഹാൻഡ്ലർ
പ്രവർത്തിക്കുന്നതിനു മുമ്പുതന്നെ ബ്രൗസറിന്റെ സൈൻ ചെയ്ത Harness
ക്രെഡൻഷ്യലിനെതിരെ Connection അഭ്യർത്ഥന അനുവദിക്കുന്നു:
ഓതന്റിക്കേറ്റ് ചെയ്യാത്ത ഒരു അഭ്യർത്ഥന ഒരിക്കലും ഇവിടെ എത്തുന്നില്ല,
ഉടമയായ Peer-നു മാത്രമാണ് സേവനം ലഭിക്കുന്നത്. രണ്ട് മൂല്യങ്ങളും
സാധൂകരിക്കുന്നു (നിലവിലുള്ള ഒരു കേവല ഡയറക്ടറി; സെപ്പറേറ്റർ ഇല്ലാത്ത ഒരു
ഫയൽ നാമം), ബോഡി നേരിട്ട് അടുത്തുള്ള ഒരു `.dsh-upload-<uuid>.part` ഫയലിലേക്ക്
സ്ട്രീം ചെയ്യുന്നു; അവസാന ബൈറ്റ് എത്തിയതിനു ശേഷം മാത്രമാണ് അത്
സ്ഥാനത്തേക്ക് പേരുമാറ്റുന്നത് — റദ്ദാക്കിയതോ പരാജയപ്പെട്ടതോ ആയ ഒരു
അപ്‌ലോഡ് യഥാർത്ഥ നാമത്തിൽ ഒന്നും അവശേഷിപ്പിക്കുന്നില്ല.

**ബ്രൗസർ ഭാഗം** — സ്വന്തമായി എഴുതിയ ഒരു lazy-CJS bundle, ഇത് shell
മുൻകൂട്ടി നൽകുന്ന അടിസ്ഥാന പാക്കേജുകൾ മാത്രമാണ് ആവശ്യപ്പെടുന്നത്
(`react`, `react-dom`). ഇത് രണ്ട് സംഭാവനകൾ രജിസ്റ്റർ ചെയ്യുന്നു:
`sidebar.panellist` വരിയും അതേ രീതിയിൽ കീ ചെയ്ത `main` പാനലും — സൈഡ്‌ബാർ
അതിനെ തിരഞ്ഞെടുക്കാൻ ആവശ്യമായ മുഴുവൻ കരാറും അതാണ്. പേജ് ത്രെഡിലെ
സാധാരണ `XMLHttpRequest` ആണ് ഓരോ ഫയലിന്റെയും പുരോഗതിയെ യഥാർത്ഥമാക്കുന്നത്:
ബ്രൗസർ യഥാർത്ഥത്തിൽ സോക്കറ്റിനു കൈമാറിയ ബൈറ്റുകളാണ്
`xhr.upload.onprogress` റിപ്പോർട്ട് ചെയ്യുന്നത്.

## ഇൻസ്റ്റാൾ

ഈ പാക്കേജ് ഒരു **bundle** ആണ് (`dsh.bundle.patch`), അതിനാൽ Plugin Manager
ഇത് ഒറ്റ വരിയായി ഇൻസ്റ്റാൾ ചെയ്യാനും അപ്‌ഡേറ്റ് ചെയ്യാനും കഴിയും:

```bash
# ഒരു ചെക്ക്ഔട്ടിൽ നിന്ന് — ഈ ഡയറക്ടറി ലിങ്ക് ചെയ്യുന്നു, മാറ്റങ്ങൾ ഉടനടി പ്രാബല്യത്തിൽ വരും
dsh plugin --profile web add /path/to/dsh-file-upload

# അല്ലെങ്കിൽ git റിമോട്ടിൽ നിന്ന്
dsh plugin --profile web add "git+https://github.com/tribesman/dsh-file-upload.git"
```

രണ്ട് വഴികളും UI-യിൽ നിന്നും സ്വീകരിക്കാം: **പ്ലഗിനുകൾ → പ്ലഗിൻ ചേർക്കുക**.

`dsh` `PATH`-ൽ ഇല്ലെങ്കിൽ, ചെക്ക്ഔട്ട് പ്രൊഫൈലിലേക്ക് സിംലിങ്ക് ചെയ്ത് വരി
കൈകൊണ്ട് ചേർക്കുക:

```yaml
# $DSH_HOME/profiles/web/cordis.patch.yml
- insert:
    - id: file-upload-panel
      name: '@dsh-plugins/file-upload'
```

```bash
ln -s /path/to/dsh-file-upload \
  "$DSH_HOME/profiles/web/node_modules/@dsh-plugins/file-upload"
```

വരിയുടെ id നിലവിലുള്ള ഏതെങ്കിലും id ആവർത്തിക്കരുത്: `file-upload` ഇതിനകം
`@deepseek-ai/dsh-client-file-upload` എന്നതിന്റേതാണ്, അത് ബ്രൗസറിലെ
പ്രോംപ്റ്റ് അറ്റാച്ച്മെന്റ് ട്രാൻസ്‌പോർട്ട് ആണ്; ഒരേ id പങ്കിടുന്ന രണ്ട്
Loader എൻട്രികളിൽ ഒന്ന് മാത്രമേ കമ്പോസ് ചെയ്യൂ. അതുകൊണ്ടാണ്
`file-upload-panel` എന്നത് ഉപയോഗിക്കുന്നത്.

പുതുതായി ചേർത്ത ഒരു Loader വരി കമ്പോസ് ചെയ്യാൻ ഹാർനെസ് ഒരിക്കൽ
റീസ്റ്റാർട്ട് ചെയ്യുക. ലൈവ് ഇൻസ്റ്റൻസിൽ, ചേർത്ത വരി റീസ്റ്റാർട്ട്
കൂടാതെ മൗണ്ട് ചെയ്യും.

ഇത് പ്രവർത്തിക്കുന്നുണ്ടെന്ന് പരിശോധിക്കുക: **ഓട്ടോമേഷൻ ടാസ്കുകൾക്കു**
നേരെ താഴെ സൈഡ്‌ബാറിൽ **ഫയൽ അപ്‌ലോഡ് ചെയ്യുക** വളരും, പേജ് ഹോസ്റ്റിന്റെ
ഹോം ഫോൾഡർ ലിസ്റ്റ് ചെയ്യും, പൂർത്തിയായ അപ്‌ലോഡ് നിങ്ങൾ തിരഞ്ഞെടുത്ത
ഫോൾഡറിൽ എത്തും:

```bash
ls -l "/the/folder/you/chose"
```

## കോൺഫിഗറേഷൻ

രണ്ട് ക്രമീകരണങ്ങളും പ്ലഗിൻ വരിയുടെ `config`-ൽ ആണ്, അതിനാൽ പ്രൊഫൈലിന്റെ
പാച്ച് പാളി അവ അപ്‌ഗ്രേഡുകൾക്കിടയിലും നിലനിർത്തുന്നു:

```yaml
- id: file-upload-panel
  name: '@dsh-plugins/file-upload'
  config:
    maxFileBytes: 1048576      # സ്വതവേ 1073741824 (1 GiB), 1024 … 16 GiB
    conflict: overwrite        # സ്വതവേ "rename"
```

| ഫീൽഡ് | സ്വതവേ | അർത്ഥം |
| --- | --- | --- |
| `maxFileBytes` | `1073741824` | ഒരു ഫയലിനുള്ള പരമാവധി പരിധി (ആ മൂല്യവും ഉൾപ്പെടെ); ഇതിലും വലിയ ബോഡി `413`-നോടെ നിരസിക്കപ്പെടും, ഒന്നും സംഭരിക്കപ്പെടുകയുമില്ല |
| `conflict` | `"rename"` | ഒരു പേര് ഇതിനകം എടുത്തിട്ടുണ്ടെങ്കിൽ അതിന്റെ അർത്ഥം: `rename` നിലവിലുള്ള ഫയൽ നിലനിർത്തി പുതിയതിനെ `name (1).ext` ആയി ഒപ്പം ഇടുന്നു; `overwrite` അതിനെ മാറ്റിസ്ഥാപിക്കുന്നു |

ഈ വരി അതിന്റെ സ്കീമ സ്വന്തമായി എഴുതിയ ഒരു Standard Schema ആയി
പ്രഖ്യാപിക്കുന്നു, അതിനാൽ മുകളിലെ മൂല്യങ്ങൾ പ്ലഗിൻ സജീവമാകുമ്പോൾ
സാധൂകരിക്കപ്പെടും, തെറ്റായ ഒരു മൂല്യം ആ വരിയെ ഒരു പിശകിനോടെ
പരാജയപ്പെടുത്തും. Plugin Manager നേറ്റീവ് Schemastery ഗ്രാഫുകൾ മാത്രമേ
വായിക്കുന്നുള്ളൂ, അതിനാൽ അതിന്റെ കോൺഫിഗറേഷൻ ഫോം ഈ വരിയുടെ സ്കീമ
പിന്തുണയ്ക്കുന്നില്ലെന്ന് റിപ്പോർട്ട് ചെയ്യുകയും ഫീൽഡുകൾ ഒന്നും
നൽകുകയും ചെയ്യുന്നില്ല: മുകളിൽ കാണിച്ചതുപോലെ പാച്ചിൽ മൂല്യങ്ങൾ
സെറ്റ് ചെയ്യുക.

## സുരക്ഷാ കുറിപ്പുകൾ

- ഈ റൂട്ട് **`/api` Connection അതിർത്തിയിലെ കൃത്യമായ ഒരു റൂട്ട്** ആണ്,
  അസംസ്കൃതമായ വെബ് സർവർ പാതയല്ല, അതിനാൽ അതിന് ബ്രൗസറിന്റെ സൈൻ ചെയ്ത
  സെഷൻ കുക്കി ആവശ്യമാണ്, ഉടമയായ Peer-നു മാത്രമേ സേവനം നൽകുന്നുള്ളൂ. സ്വന്തമായി
  Host/Origin ഇളവുകളും അത് ചേർക്കുന്നില്ല.
- ഓതന്റിക്കേറ്റ് ചെയ്ത ഓപ്പറേറ്റർ ചൂണ്ടിക്കാണിക്കുന്ന ഇടത്തെല്ലാം, DSH
  പ്രോസസിന്റെ അനുമതികളോടെ റൂട്ട് എഴുതുന്നു — വർക്ക്സ്പേസ് ഡയറക്ടറി
  പിക്കറിനും `bash` ഉപകരണത്തിനും ഇതിനകം ഉള്ള അതേ പരിധി. ലക്ഷ്യസ്ഥാനം
  ഇതിനകം നിലവിലുണ്ടായിരിക്കണം; പ്ലഗിൻ ഫോൾഡറുകൾ സൃഷ്ടിക്കുന്നില്ല.
- ബ്രൗസർ ഒരു ഫോൾഡറും ഒരു ഫയൽ നാമവും മാത്രമേ പറയുന്നുള്ളൂ, ഫോൾഡറിനുള്ളിലെ
  പാതയല്ല: നാമത്തിൽ `.` ഇല്ല, സെപ്പറേറ്ററും ഇല്ല, അതിനാൽ ഒരു അഭ്യർത്ഥനയ്ക്കും
  തിരഞ്ഞെടുത്ത ഫോൾഡറിൽ നിന്ന് പുറത്തുകടക്കാനാവില്ല.
- താൽക്കാലിക ഫയലുകൾ അവയുടെ ലക്ഷ്യത്തിനു സമീപം സൃഷ്ടിക്കപ്പെടുകയും പരാജയത്തിലോ
  റദ്ദാക്കലിലോ നീക്കം ചെയ്യപ്പെടുകയും ചെയ്യുന്നു; എല്ലാ ബൈറ്റുകളും എത്തിയാൽ മാത്രമേ
  അന്തിമ നാമത്തിൽ എന്തെങ്കിലും അവശേഷിക്കൂ.

## അറിയപ്പെടുന്ന പരിമിതികൾ

- ഒരു പേജ് സന്ദർശനത്തിന് ഒരു അപ്‌ലോഡ് ക്യൂ: ലിസ്റ്റ് പേജിനുള്ളിൽ മാത്രമുള്ളതാണ്,
  അപ്‌ലോഡിനിടയിൽ പേജ് വിട്ടാലും കൈമാറ്റം തുടരും (ഫയൽ ഹോസ്റ്റ് തന്നെ പൂർത്തിയാക്കും),
  പക്ഷേ വരികൾ മറന്നുപോകും.
- പിക്കറിൽ ഫോൾഡർ സൃഷ്ടിക്കലില്ല, തുടരാനുള്ള സൗകര്യവുമില്ല: പരാജയപ്പെട്ട ഒരു
  അപ്‌ലോഡ് ആദ്യ ബൈറ്റിൽ നിന്നു തന്നെ വീണ്ടും തുടങ്ങും.
- പിക്കർ ഫോൾഡറുകൾ മാത്രമാണ് ലിസ്റ്റ് ചെയ്യുന്നത്, വെട്ടിച്ചുരുക്കിയ തലങ്ങൾ പേജിംഗിനു
  പകരം `truncated` എന്ന് റിപ്പോർട്ട് ചെയ്യുന്നു.
- `maxFileBytes`-നുള്ള ക്ലയന്റ്-സൈഡ് പ്രീഫ്ലൈറ്റ് പേജിനില്ല: വളരെ വലിയ ഒരു
  ഫയൽ കൈമാറ്റത്തിനു ശേഷം ഹോസ്റ്റ് നിരസിക്കും.
- ഹോസ്റ്റ് പിശക് വാചകം ഇംഗ്ലീഷിൽ എഴുതുന്നു, errno കോഡ് സന്ദേശത്തിൽ
  നിലനിർത്തുന്നു.

## ഡെവലപ്മെന്റ്

```bash
npm test        # node --test: റൂട്ടിനും bundle-നും വേണ്ടി 22 കേസുകൾ
npm run check   # രണ്ട് ഭാഗങ്ങൾക്കുമുള്ള സിന്റാക്സ് ഗേറ്റ്
```

ഹോസ്റ്റ് ടെസ്റ്റുകൾ യഥാർത്ഥ `Request`/`Response` ഒബ്ജക്റ്റുകളിലൂടെയും ഒരു
യഥാർത്ഥ ടെമ്പ് ഡയറക്ടറിയിലൂടെയും റൂട്ട് പ്രവർത്തിപ്പിക്കുന്നു, അതിനാൽ
ബൈറ്റ് പാത, കോൺഫ്ലിക്റ്റ് നയങ്ങൾ, വലിപ്പ പരിധി, റദ്ദാക്കൽ, പരാജയ സന്ദേശം
എന്നിവ ഒരു ഹാർനെസ് കൂടാതെ തന്നെ പരിശോധിക്കുന്നു. ബ്രൗസർ ടെസ്റ്റുകൾ
ഒരു സ്റ്റബ് React-ഉം DOM-ഉം ഉള്ള ഒരു VM-ൽ bundle പ്രവർത്തിപ്പിക്കുന്നു,
അതിനാൽ അവയ്ക്ക് ഹാർനെസ്സോ ബ്രൗസറോ ആവശ്യമില്ല.
