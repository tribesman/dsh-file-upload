# @dsh-plugins/file-upload

**Μια γραμμή με συνδετήρα κάτω από την ενότητα Εργασίες αυτοματισμού** στην πλαϊνή στήλη web του [DSH](https://github.com/deepseek-ai/deepseek-harness), που ανοίγει μια σελίδα μεταφόρτωσης: διαλέξτε έναν φάκελο στον Host με τον ίδιο τρόπο που κάνει το παράθυρο του χώρου εργασίας, επιλέξτε πολλά αρχεία μαζί και παρακολουθήστε το καθένα να μεταφορτώνεται με τη δική του γραμμή προόδου.

## Γιατί

Το DSH μπορεί να μετακινεί byte *έξω* από τον χώρο εργασίας ([`@dsh-plugins/file-download`](https://github.com/tribesman/dsh-file-download)) και προετοιμάζει συνημμένα του browser για ένα μόνο prompt, αλλά δεν υπήρχε τρόπος να βάλετε πολλά υπάρχοντα αρχεία σε έναν φάκελο στον διακομιστή χωρίς κέλυφος στον Host. Αυτό το πρόσθετο προσθέτει το κομμάτι που έλειπε, στη θέση όπου ζουν τα άλλα καθολικά πάνελ.

## Πού εμφανίζεται

| Σημείο | Τι |

| Αριστερή πλαϊνή στήλη | Μια γραμμή **Μεταφόρτωση αρχείου** με εικονίδιο συνδετήρα, ακριβώς κάτω από τις **Εργασίες αυτοματισμού** (`order: 11`) |
| Κεντρική στήλη | Η σελίδα μεταφόρτωσης, που ανοίγει επιλέγοντας αυτή τη γραμμή |

<img src="../assets/upload-page.png" alt="Η σελίδα Μεταφόρτωση αρχείου χωρίς επιλεγμένο φάκελο προορισμού ακόμη: η γραμμή στην πλαϊνή στήλη βρίσκεται κάτω από τις Εργασίες αυτοματισμού και η σελίδα δείχνει μια κάρτα προορισμού και μια διακεκομμένη περιοχή απόθεσης" width="1200" />

Όλα στη σελίδα είναι μία ροή:

1. **Φάκελος προορισμού** — η *Επιλογή φακέλου* ανοίγει ένα παράθυρο μέσα στην εφαρμογή, που τροφοδοτείται από την ίδια την καταγραφή καταλόγων του Host (`ctx.uiWorkspace.listDirectory`, το ίδιο βασικό στοιχείο πίσω από την **Επιλογή καταλόγου χώρου εργασίας**): άλματα με ψίχουλα διαδρομής, μια διαδρομή που επεξεργάζεται με κλικ, διακόπτης κρυφών φακέλων και μια επιβεβαίωση *Επιλογή αυτού του φακέλου*. Η λίστα φακέλων έρχεται από τον Host, οπότε λειτουργεί από απομακρυσμένο browser όπου δεν υπάρχει επιλογέας του λειτουργικού συστήματος.

   <img src="../assets/folder-picker.png" alt="Το παράθυρο Επιλογή φακέλου στον διακομιστή: τα ψίχουλα διαδρομής δείχνουν τον Αρχικό φάκελο και τον φάκελο demo, με τα archive, photos και reports στη λίστα" width="1200" />

2. **Επιλογή αρχείων** — ο επιλογέας αρχείων της σελίδας δέχεται πολλά αρχεία μαζί, και αρχεία που αφήνονται οπουδήποτε στη σελίδα μπαίνουν στην ίδια ουρά.
3. **Μεταφόρτωση αρχείων** — η ουρά προχωρά ένα αρχείο τη φορά· κάθε γραμμή δείχνει τον μετρητή αποσταλμένων byte, μια γραμμή προόδου και μια ετικέτα κατάστασης. Μια γραμμή που απέτυχε κρατά το μήνυμά της και προσφέρει **Νέα προσπάθεια**· η **Ακύρωση μεταφόρτωσης** σταματά την ουρά και αφήνει τις υπόλοιπες γραμμές έτοιμες.

## Πώς λειτουργεί

**Το τμήμα του Host** — μία πιστοποιημένη διαδρομή streaming στο κοινό όριο `/api`:

```
POST /api/file-upload/write?dir=<absolute folder>&name=<file name>
content-type: application/octet-stream
```

Βρίσκεται στο `ctx.connection.fetch`, οπότε το Connection δέχεται το αίτημα βάσει του υπογεγραμμένου διαπιστευτηρίου Harness του browser πριν εκτελεστεί αυτός ο handler: ένα μη πιστοποιημένο αίτημα δεν φτάνει ποτέ σε αυτόν και εξυπηρετείται μόνο το Peer του ιδιοκτήτη. Και οι δύο συντεταγμένες επικυρώνονται (ένας απόλυτος, υπάρχων κατάλογος· ένα σκέτο όνομα αρχείου χωρίς διαχωριστικό), και το σώμα μεταφέρεται με streaming απευθείας σε ένα γειτονικό αρχείο `.dsh-upload-<uuid>.part`, το οποίο μετονομάζεται στη θέση του μόνο αφού φτάσει το τελευταίο byte — μια διακοπτόμενη ή αποτυχημένη μεταφόρτωση δεν αφήνει τίποτα πίσω με το πραγματικό όνομα.

**Το τμήμα του browser** — ένα χειρόγραφο bundle lazy-CJS που απαιτεί μόνο τη βάση που παρέχει το shell (`react`, `react-dom`). Καταχωρεί δύο συνεισφορές: τη γραμμή `sidebar.panellist` και το πάνελ `main` με το ίδιο κλειδί, και αυτό είναι όλο το συμβόλαιο που χρειάζεται η πλαϊνή στήλη για να το επιλέξει. Το απλό `XMLHttpRequest` στο νήμα της σελίδας είναι αυτό που κάνει την πρόοδο ανά αρχείο πραγματική: το `xhr.upload.onprogress` αναφέρει byte που ο browser έχει πραγματικά παραδώσει στο socket.

## Εγκατάσταση

Το πακέτο είναι ένα **bundle** (`dsh.bundle.patch`), οπότε ο Διαχειριστής προσθέτων μπορεί να το εγκαταστήσει και να το ενημερώσει ως μία γραμμή:

```bash
# από ένα checkout — συνδέει αυτόν τον κατάλογο, οι αλλαγές μένουν ζωντανές
dsh plugin --profile web add /path/to/dsh-file-upload

# ή από το απομακρυσμένο git
dsh plugin --profile web add "git+https://github.com/tribesman/dsh-file-upload.git"
```

Και οι δύο διαδρομές μπορούν να γίνουν και από τη διεπαφή: **Πρόσθετα → Προσθήκη πρόσθετου**.

Χωρίς το `dsh` στο `PATH`, δημιουργήστε έναν συμβολικό σύνδεσμο του checkout στο προφίλ και προσθέστε τη γραμμή με το χέρι:

```yaml
# $DSH_HOME/profiles/web/cordis.patch.yml
- insert:
    - id: file-upload-panel
      name: '@dsh-plugins/file-upload'
```

```bash
ln -s /path/to/dsh-file-upload \
  "$DSH_HOME/profiles/web/node_modules/@dsh-plugins/file-upload"
```

Το id της γραμμής δεν πρέπει να επαναλαμβάνει ένα από τα παρεχόμενα: το `file-upload` ανήκει ήδη στο `@deepseek-ai/dsh-client-file-upload`, τη μεταφορά συνημμένων του prompt στον browser, και δύο καταχωρίσεις Loader που μοιράζονται ένα id συνθέτουν μόνο μία από αυτές. Εξ ου το `file-upload-panel`.

Επανεκκινήστε το harness μία φορά ώστε μια νεοπροσθετημένη γραμμή Loader να συντεθεί. Σε μια ενεργή εγκατάσταση, μια γραμμή που εισάγεται προσαρτάται χωρίς επανεκκίνηση.

Ελέγξτε ότι λειτουργεί: η πλαϊνή στήλη αποκτά **Μεταφόρτωση αρχείου** ακριβώς κάτω από τις **Εργασίες αυτοματισμού**, η σελίδα εμφανίζει τον αρχικό φάκελο του Host και μια ολοκληρωμένη μεταφόρτωση καταλήγει στον φάκελο που διαλέξατε:

```bash
ls -l "/the/folder/you/chose"
```

## Ρύθμιση

Και οι δύο παράμετροι ζουν στο `config` της γραμμής του πρόσθετου, οπότε το επίπεδο patch του προφίλ τις διατηρεί στις αναβαθμίσεις:

```yaml
- id: file-upload-panel
  name: '@dsh-plugins/file-upload'
  config:
    maxFileBytes: 1048576      # προεπιλογή 1073741824 (1 GiB), 1024 … 16 GiB
    conflict: overwrite        # προεπιλογή "rename"
```

| Πεδίο | Προεπιλογή | Σημασία |
| --- | --- | --- |
| `maxFileBytes` | `1073741824` | Ανώτατο όριο για ένα αρχείο, συμπεριλαμβανομένης της τιμής· ένα μεγαλύτερο σώμα απορρίπτεται με `413` και δεν αποθηκεύεται τίποτα |
| `conflict` | `"rename"` | Τι σημαίνει ένα κατειλημμένο όνομα: το `rename` διατηρεί το υπάρχον αρχείο και τοποθετεί το νέο ως `name (1).ext`· το `overwrite` το αντικαθιστά |

Η γραμμή δηλώνει το σχήμα της ως ένα χειρόγραφο Standard Schema, οπότε οι παραπάνω τιμές επικυρώνονται όταν ενεργοποιείται το πρόσθετο και μια λανθασμένη τιμή κάνει τη γραμμή να αποτύχει με σφάλμα. Ο Διαχειριστής προσθέτων διαβάζει μόνο εγγενή γραφήματα Schemastery, γι' αυτό η φόρμα ρύθμισής του αναφέρει το σχήμα αυτής της γραμμής ως μη υποστηριζόμενο και δεν προσφέρει πεδία: ορίστε τις τιμές στο patch, όπως φαίνεται παραπάνω.

## Σημειώσεις ασφαλείας

- Η διαδρομή είναι μια **ακριβής διαδρομή στο όριο `/api` του Connection**, όχι μια ακατέργαστη διαδρομή διακομιστή web, οπότε απαιτεί το υπογεγραμμένο cookie συνεδρίας του browser και εξυπηρετεί μόνο το Peer του ιδιοκτήτη. Επίσης δεν προσθέτει καμία δική της χαλάρωση Host/Origin.
- Η διαδρομή γράφει όπου την κατευθύνει ο πιστοποιημένος χειριστής, με τα δικαιώματα της διεργασίας DSH — η ίδια εμβέλεια που έχουν ήδη ο επιλογέας καταλόγου του χώρου εργασίας και το εργαλείο `bash`. Ο φάκελος προορισμού πρέπει να υπάρχει ήδη· το πρόσθετο δεν δημιουργεί φακέλους.
- Ο browser δηλώνει έναν φάκελο και ένα όνομα αρχείου, ποτέ μια διαδρομή μέσα σε αυτόν: το όνομα δεν περιέχει `.` ούτε διαχωριστικά, οπότε ένα αίτημα δεν μπορεί να ξεφύγει από τον φάκελο που διαλέξατε.
- Τα προσωρινά αρχεία δημιουργούνται δίπλα στον προορισμό τους και αφαιρούνται σε αποτυχία ή ακύρωση· τίποτα δεν μένει με το τελικό όνομα αν δεν έχουν φτάσει όλα τα byte.

## Γνωστοί περιορισμοί

- Μία ουρά μεταφόρτωσης ανά επίσκεψη στη σελίδα: η λίστα είναι τοπική στη σελίδα και η έξοδος από τη σελίδα στη μέση της μεταφόρτωσης κρατά τη μεταφορά σε λειτουργία (ο Host ολοκληρώνει το αρχείο) αλλά ξεχνά τις γραμμές.
- Χωρίς δημιουργία φακέλων στον επιλογέα και χωρίς συνέχιση: μια αποτυχημένη μεταφόρτωση ξεκινά από το πρώτο byte.
- Ο επιλογέας εμφανίζει μόνο φακέλους και τα κομμένα επίπεδα αναφέρουν `truncated` αντί για σελιδοποίηση.
- Η σελίδα δεν έχει προκαταρκτικό έλεγχο στην πλευρά του πελάτη για το `maxFileBytes`: ένα υπερβολικά μεγάλο αρχείο απορρίπτεται από τον Host μετά τη μεταφορά.
- Ο Host γράφει το κείμενο σφάλματος στα αγγλικά και κρατά τον κωδικό errno στο μήνυμα.

## Ανάπτυξη

```bash
npm test        # node --test: 22 περιπτώσεις στη διαδρομή και στο bundle
npm run check   # έλεγχος σύνταξης για τα δύο τμήματα
```

Οι δοκιμές του Host οδηγούν τη διαδρομή μέσα από πραγματικά αντικείμενα `Request`/`Response` και έναν πραγματικό προσωρινό κατάλογο, οπότε καλύπτουν τη διαδρομή των byte, τις πολιτικές σύγκρουσης, το ανώτατο όριο μεγέθους, την ακύρωση και το κείμενο αποτυχίας χωρίς harness. Οι δοκιμές του browser εκτελούν το bundle σε μια VM με ένα stub των React και DOM, οπότε δεν χρειάζονται ούτε harness ούτε browser.
