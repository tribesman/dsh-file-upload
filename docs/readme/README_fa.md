# @dsh-plugins/file-upload

یک **ردیف گیرهٔ کاغذ زیر کار‌های خودکارسازی** در نوار کناری وب [DSH](https://github.com/deepseek-ai/deepseek-harness)
که صفحهٔ بارگذاری را باز می‌کند: پوشه‌ای روی میزبان را همانطور که پنجرهٔ فضای کاری
انجام می‌دهد انتخاب کنید، چند فایل را همزمان بردارید، و بارگذاری هر یک را با نوار
پیشرفت خودش ببینید.

## چرا

DSH می‌تواند بایت‌ها را *از* فضای کاری بیرون ببرد ([`@dsh-plugins/file-download`](https://github.com/tribesman/dsh-file-download))
و پیوست‌های مرورگر را برای یک پیام آماده می‌کند، اما هیچ راهی نبود که چند فایل
موجود را بدون یک شل روی میزبان در پوشه‌ای روی سرور گذاشت. این افزونه همان همتای گمشده را
اضافه می‌کند، در همان جایی که دیگر پنل‌های سراسری قرار دارند.

## کجا دیده می‌شود

| جایگاه | چه چیزی |
| --- | --- |
| نوار کناری چپ | ردیفی با عنوان **بارگذاری فایل** و نماد گیرهٔ کاغذ، درست زیر **کار‌های خودکارسازی** (`order: 11`) |
| ستون اصلی | صفحهٔ بارگذاری، که با انتخاب همان ردیف باز می‌شود |

<img src="../assets/upload-page.png" alt="صفحهٔ بارگذاری فایل پیش از انتخاب پوشهٔ مقصد: ردیف نوار کناری زیر کار‌های خودکارسازی نشسته، و صفحه یک کارت مقصد و یک ناحیهٔ رها‌کردن خط‌چین نشان می‌دهد" width="1200" />

همه‌چیز در این صفحه یک جریان واحد است:

1. **پوشهٔ مقصد** — دکمهٔ *انتخاب پوشه* یک پنجرهٔ درون‌برنامه‌ای را باز می‌کند که از
   فهرست پوشه‌های خودِ میزبان تغذیه می‌شود (`ctx.uiWorkspace.listDirectory`، همان
   سازوکار پایه‌ای که پشت **انتخاب پوشهٔ فضای کاری** است): پرش‌های مسیر راهنما
   (breadcrumb)، مسیری که با کلیک ویرایش می‌شود، کلید نمایش پوشه‌های پنهان، و
   تأیید *انتخاب این پوشه*. فهرست پوشه‌ها از میزبان می‌آید، بنابراین از یک مرورگر
   راه دور که هیچ انتخابگر سیستم‌عاملی ندارد هم کار می‌کند.

   <img src="../assets/folder-picker.png" alt="پنجرهٔ انتخاب پوشه روی سرور: مسیر راهنما پوشهٔ خانه (Home) و پوشهٔ demo را نشان می‌دهد، و archive، photos و reports فهرست شده‌اند" width="1200" />

2. **انتخاب فایل‌ها** — انتخابگر فایل صفحه چند فایل را همزمان می‌پذیرد، و فایل‌هایی
   که هر جای صفحه رها شوند به همان صف می‌پیوندند.
3. **بارگذاری فایل‌ها** — صف هر بار یک فایل را پیش می‌برد؛ هر ردیف شمارندهٔ
   بایت‌های فرستاده‌شده، یک نوار پیشرفت و یک برچسب وضعیت را نشان می‌دهد. ردیف
   ناموفق پیام خود را نگه می‌دارد و **تلاش دوباره** را پیشنهاد می‌کند؛ **لغو
   بارگذاری** صف را متوقف می‌کند و ردیف‌های باقیمانده را آماده می‌گذارد.

   <img src="../assets/uploading.png" alt="بارگذاری در جریان: ردیف اول ۲۱۵ مگابایت از ۸۰۰ مگابایت را با نواری نیمه‌پر و برچسب «در حال بارگذاری» گزارش می‌دهد، ردیف‌های دیگر با وضعیت «آماده» منتظرند، و سرصفحه گزینهٔ «لغو بارگذاری» را نشان می‌دهد" width="1200" />

## چگونه کار می‌کند

**نیمهٔ میزبان** — یک مسیر جریانیِ احراز هویت‌شده روی حصار مشترک `/api`:

```
POST /api/file-upload/write?dir=<absolute folder>&name=<file name>
content-type: application/octet-stream
```

این مسیر روی `ctx.connection.fetch` نشسته است، بنابراین Connection پیش از اجرای
این گرداننده، درخواست را در برابر اعتبارنامهٔ امضا‌شدهٔ Harness از سوی مرورگر
می‌پذیرد: درخواست بدون احراز هویت هرگز به آن نمی‌رسد، و تنها Peer مالک سرو می‌شود.
هر دو مختصات اعتبارسنجی می‌شوند (یک پوشهٔ مطلق و موجود؛ یک نام فایل تنها و بدون
جداکننده)، و بدنه مستقیم به فایلی همسایه با نام `.dsh-upload-<uuid>.part` جریان
می‌یابد که تنها پس از رسیدن آخرین بایت به جای خود تغییر نام می‌یابد — بارگذاری
قطع‌شده یا ناموفق چیزی زیر نام واقعی باقی نمی‌گذارد.

**نیمهٔ مرورگر** — یک bundle دستنویس lazy-CJS که تنها به پایهٔ تزریق‌شده توسط پوسته
نیاز دارد (`react`، `react-dom`). دو مشارکت ثبت می‌کند: ردیف `sidebar.panellist` و
پنل `main` با همان کلید، و این تمام قراردادی است که نوار کناری برای انتخاب آن لازم
دارد. همان `XMLHttpRequest` ساده در رشتهٔ صفحه است که پیشرفت هر فایل را واقعی
می‌کند: `xhr.upload.onprogress` بایت‌هایی را گزارش می‌کند که مرورگر واقعاً به سوکت
سپرده است.

## نصب

این بسته یک **bundle** است (`dsh.bundle.patch`)، بنابراین Plugin Manager می‌تواند
آن را به‌عنوان یک ردیف نصب و به‌روزرسانی کند:

```bash
# از یک checkout — این پوشه را پیوند می‌دهد، ویرایش‌ها زنده می‌مانند
dsh plugin --profile web add /path/to/dsh-file-upload

# یا از ریموت git
dsh plugin --profile web add "git+https://github.com/tribesman/dsh-file-upload.git"
```

هر یک از این دو مسیر را می‌توان از رابط کاربری هم رفت: **افزونه‌ها ← افزودن افزونه**.

بدون `dsh` روی `PATH`، checkout را به‌صورت symlink در پروفایل قرار دهید و
ردیف را دستی اضافه کنید:

```yaml
# $DSH_HOME/profiles/web/cordis.patch.yml
- insert:
    - id: file-upload-panel
      name: '@dsh-plugins/file-upload'
```

```bash
ln -s /path/to/dsh-file-upload \
  "$DSH_HOME/profiles/web/node_modules/@dsh-plugins/file-upload"
```

شناسهٔ ردیف نباید شناسهٔ یک ردیف از پیش ارسال‌شده را تکرار کند: `file-upload` از
پیش از آنِ `@deepseek-ai/dsh-client-file-upload` است، یعنی حامل پیوست اعلان در
مرورگر، و دو ورودی Loader که یک شناسه را شریکاند تنها یکی از آن‌ها را ترکیب
می‌کنند. از همین رو `file-upload-panel`.

harness را یک بار دوباره راهاندازی کنید تا ردیف تازهٔ Loader ترکیب شود. در یک
نمونهٔ زنده، ردیف درج‌شده بدون راهاندازی دوباره mount می‌شود.

بررسی کنید که کار می‌کند: نوار کناری با **بارگذاری فایل** درست زیر **کار‌های
خودکارسازی** بزرگ‌تر می‌شود، صفحه پوشهٔ خانهٔ میزبان را فهرست می‌کند، و بارگذاری
تمام‌شده در پوشه‌ای می‌نشیند که انتخاب کردید:

```bash
ls -l "/the/folder/you/chose"
```

## پیکربندی

هر دو تنظیم در `config` ردیف افزونه قرار دارند، بنابراین لایهٔ patch پروفایل
آن‌ها را در طول ارتقا‌ها نگه می‌دارد:

```yaml
- id: file-upload-panel
  name: '@dsh-plugins/file-upload'
  config:
    maxFileBytes: 1048576      # پیش‌فرض 1073741824 (1 GiB), 1024 … 16 GiB
    conflict: overwrite        # پیش‌فرض "rename"
```

| فیلد | پیش‌فرض | معنا |
| --- | --- | --- |
| `maxFileBytes` | `1073741824` | بیشینهٔ مجاز برای یک فایل، خودِ این مقدار هم پذیرفته می‌شود؛ بدنهٔ بزرگ‌تر با `413` رد می‌شود و چیزی ذخیره نمی‌شود |
| `conflict` | `"rename"` | معنای نامی که اشغال شده: `rename` فایل موجود را نگه می‌دارد و فایل جدید را با نام `name (1).ext` می‌نشاند؛ `overwrite` آن را جایگزین می‌کند |

ردیف طرحوارهٔ خود را به‌صورت یک Standard Schema دستنویس اعلام می‌کند، بنابراین
مقادیر بالا هنگام فعال شدن افزونه اعتبارسنجی می‌شوند و یک مقدار بد باعث می‌شود ردیف با خطا
شکست بخورد. Plugin Manager تنها نمودار‌های بومی Schemastery را می‌خواند، بنابراین
فرم پیکربندی آن طرحوارهٔ این ردیف را پشتیبانی‌نشده گزارش می‌کند و هیچ فیلدی پیشنهاد
نمی‌دهد: مقادیر را در patch همانطور که بالا نشان داده شد بگذارید.

## نکات امنیتی

- این مسیر یک **مسیر دقیق روی حصار Connection در `/api`** است، نه یک مسیر خام
  وب‌سرور، بنابراین به کوکی نشست امضا‌شدهٔ مرورگر نیاز دارد و تنها به Peer مالک سرو
  می‌کند. هیچ سهلگیری Host/Origin هم از خودش اضافه نمی‌کند.
- مسیر هر جایی که اپراتور احراز هویت‌شده اشاره کند می‌نویسد، با مجوز‌های فرایند
  DSH — همان دسترسی‌ای که انتخابگر پوشهٔ فضای کاری و ابزار `bash` از قبل دارند.
  پوشهٔ مقصد باید از قبل وجود داشته باشد؛ افزونه پوشه نمی‌سازد.
- مرورگر یک پوشه و یک نام فایل را اعلام می‌کند، هرگز مسیری درون آن را: نام بدون `.`
  و بدون جداکننده است، بنابراین هیچ درخواستی نمی‌تواند از پوشهٔ انتخاب‌شده بگریزد.
- فایل‌های موقت کنار هدفشان ساخته می‌شوند و در صورت شکست یا لغو حذف می‌شوند؛ چیزی
  زیر نام نهایی نمی‌ماند مگر آنکه هر بایت رسیده باشد.

## محدودیت‌های شناخته‌شده

- یک صف بارگذاری برای هر بازدید از صفحه: فهرست مخصوص همان صفحه است، و ترک صفحه در
  میانهٔ بارگذاری انتقال را ادامه می‌دهد (میزبان فایل را تمام می‌کند) اما ردیف‌ها
  را فراموش می‌کند.
- بدون ساخت پوشه در انتخابگر و بدون ادامه: بارگذاری ناموفق از اولین بایت دوباره
  شروع می‌شود.
- انتخابگر فقط پوشه‌ها را فهرست می‌کند، و سطوح بریده‌شده به‌جای صفحهبندی
  `truncated` را گزارش می‌کنند.
- صفحه هیچ پیش‌بررسی سمت کلاینتی برای `maxFileBytes` ندارد: فایل بزرگ‌تر پس از
  انتقال توسط میزبان رد می‌شود.
- میزبان متن خطا را انگلیسی می‌نویسد و کد errno را در پیام نگه می‌دارد.

## توسعه

```bash
npm test        # node --test: 22 مورد روی مسیر و bundle
npm run check   # دروازهٔ نحوی روی هر دو نیمه
```

تست‌های میزبان مسیر را با اشیای واقعی `Request`/`Response` و یک پوشهٔ موقت واقعی
می‌رانند، بنابراین مسیر بایت‌ها، سیاست‌های تعارض، سقف حجم، لغو و متن شکست را بدون
harness پوشش می‌دهند. تست‌های مرورگر bundle را در یک ماشین مجازی (VM) با React و
DOM ساختگی اجرا می‌کنند، بنابراین نه به harness نیاز دارند نه به مرورگر.
