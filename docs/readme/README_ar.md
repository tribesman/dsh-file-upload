# @dsh-plugins/file-upload

صفّ **مشبك ورق تحت مهام الأتمتة** في الشريط الجانبي لواجهة الويب [DSH](https://github.com/deepseek-ai/deepseek-harness)
يفتح صفحة تحميل: اختر مجلدًا على المضيف بالطريقة نفسها التي تعمل بها نافذة مساحة العمل،
واختر عدة ملفات دفعة واحدة، وراقب تحميل كل ملف بشريط التقدم الخاص به.

<img src="../assets/uploaded.png" alt="صفحة تحميل الملف بعد انتهاء تحميل ثلاثة ملفات: صف مشبك الورق مُحدَّد في الشريط الجانبي الأيسر، والمجلد الوجهة مُعيَّن، وكل صف يُظهر شريطًا أخضر ووسم «تم التحميل»" width="1200" />

<sub>أسماء مساحات العمل والجلسات في الشريط الجانبي مطموسة.</sub>

</div>

## لماذا

يستطيع DSH إخراج البايتات *من* مساحة العمل ([`@dsh-plugins/file-download`](https://github.com/tribesman/dsh-file-download))
ويُجهّز مرفقات المتصفح لطلب واحد، لكن لم تكن هناك طريقة لوضع عدة ملفات موجودة في
مجلد على الخادم دون صدفة أوامر على المضيف. توفّر هذه الإضافة النظير المفقود، في الموضع
الذي تعيش فيه اللوحات العامة الأخرى.

## أين يظهر

| الموضع | ماذا |
| --- | --- |
| الشريط الجانبي الأيسر | صفّ **تحميل ملف** برمز مشبك الورق، أسفل **مهام الأتمتة** مباشرةً (`order: 11`) |
| العمود الرئيسي | صفحة التحميل، تُفتح باختيار ذلك الصف |

<img src="../assets/upload-page.png" alt="صفحة تحميل الملف دون اختيار مجلد وجهة بعد: صف الشريط الجانبي يقع تحت مهام الأتمتة، وتعرض الصفحة بطاقة للمجلد الوجهة ومنطقة إسقاط متقطعة الحدود" width="1200" />

كل ما في الصفحة جريان واحد:

1. **المجلد الوجهة** — يفتح زر *اختيار مجلد* نافذة داخل التطبيق تعتمد على فهرسة
   المضيف نفسه للمجلدات (`ctx.uiWorkspace.listDirectory`، وهي الوظيفة الأولية نفسها التي
   تقوم عليها **تحديد مجلد مساحة العمل**): انتقالات عبر شريط المسار، ومسار قابل
   للنقر للتحرير، ومفتاح للمجلدات المخفية، وزر تأكيد *اختيار هذا المجلد*.
   تأتي قائمة المجلدات من المضيف، لذا تعمل من متصفح بعيد لا يوجد فيه منتقي من نظام التشغيل.

   <img src="../assets/folder-picker.png" alt="نافذة اختيار مجلد على الخادم: يُظهر شريط المسار المجلد الرئيسي Home ومجلد demo، مع سرد archive وphotos وreports" width="1200" />

2. **اختيار الملفات** — يقبل منتقي الملفات في الصفحة عدة ملفات دفعة واحدة،
   والملفات التي تُسقَط في أي مكان على الصفحة تنضم إلى قائمة الانتظار نفسها.
3. **تحميل الملفات** — تعمل قائمة الانتظار على ملف واحد في كل مرة؛ ويعرض كل صف
   عدّاد البايتات المُرسَلة، وشريط تقدم، ووسم حالة. يحتفظ الصف الفاشل برسالته
   ويعرض **إعادة المحاولة**؛ ويوقف **إلغاء التحميل** قائمة الانتظار ويترك الصفوف
   المتبقية جاهزة.

   <img src="../assets/uploading.png" alt="تحميل جارٍ: يعرض الصف الأول 215 ميغابايت من أصل 800 ميغابايت مع شريط نصف ممتلئ ووسم «جارٍ التحميل»، وتنتظر الصفوف الأخرى بحالة «جاهز»، ويعرض رأس الصفحة «إلغاء التحميل»" width="1200" />

## كيف يعمل

**النصف الخاص بالمضيف** — مسار بث واحد موثَّق على الحاجز المشترك `/api`:

```
POST /api/file-upload/write?dir=<absolute folder>&name=<file name>
content-type: application/octet-stream
```

يستند إلى `ctx.connection.fetch`، لذا تُجيز Connection الطلب وفق اعتماد Harness
الموقَّع الآتي من المتصفح قبل أن يعمل هذا المعالج: فالطلب غير الموثَّق لا يصل إليه
أبدًا، ولا يُخدَم إلا الـ Peer المالك. ويُتحقَّق من الإحداثيّين كليهما (مجلد مطلق
وموجود؛ واسم ملف واحد مجرَّد بلا فاصل)، ويتدفق الجسم مباشرة إلى ملف شقيق باسم
`.dsh-upload-<uuid>.part` لا يُنقل إلى موضعه بإعادة التسمية إلا بعد وصول آخر بايت —
فالتحميل المقطوع أو الفاشل لا يترك شيئًا خلفه بالاسم الحقيقي.

**النصف الخاص بالمتصفح** — حزمة lazy-CJS مكتوبة يدويًا لا تتطلب سوى الأساس الذي
تزرعه القشرة (`react`، `react-dom`). تسجّل مساهمتين: صفّ `sidebar.panellist`
واللوحة `main` بالمفتاح نفسه، وهذا هو العقد كله الذي يحتاجه الشريط الجانبي
لاختيارها. و`XMLHttpRequest` العادي في خيط الصفحة هو ما يجعل تقدم كل ملف حقيقيًا:
يبلّغ `xhr.upload.onprogress` عن البايتات التي سلّمها المتصفح فعليًا إلى المقبس.

## التثبيت

الحزمة عبارة عن **bundle** (`dsh.bundle.patch`)، لذا يستطيع Plugin Manager تثبيتها
وتحديثها كصفّ واحد:

```bash
# من نسخة مستخرجة — يربط هذا المجلد، وتبقى التعديلات حيّة
dsh plugin --profile web add /path/to/dsh-file-upload

# أو من المستودع البعيد على git
dsh plugin --profile web add "git+https://github.com/tribesman/dsh-file-upload.git"
```

يمكن اتباع أي من الطريقين من الواجهة أيضًا: **الإضافات ← إضافة مكوّن إضافي**.

إذا لم يكن `dsh` موجودًا على `PATH`، فاربط نسخة المستودع برابط رمزي داخل الملف
الشخصي وأضف الصف يدويًا:

```yaml
# $DSH_HOME/profiles/web/cordis.patch.yml
- insert:
    - id: file-upload-panel
      name: '@dsh-plugins/file-upload'
```

```bash
ln -s /path/to/dsh-file-upload \
  "$DSH_HOME/profiles/web/node_modules/@dsh-plugins/file-upload"
```

يجب ألا يكرّر معرّف الصف معرّفًا مشحونًا: فالمعرّف `file-upload` ينتمي أصلًا إلى
`@deepseek-ai/dsh-client-file-upload`، أي ناقل مرفقات الطلب في المتصفح، ومدخلان
في Loader يتشاركان المعرّف نفسه يركّبان واحدًا منهما فقط. ومن هنا جاء
`file-upload-panel`.

أعِد تشغيل harness مرة واحدة حتى يُركَّب صفّ Loader المضاف حديثًا. وفي نسخة قيد
التشغيل يُثبَّت الصف المُدرَج دون إعادة تشغيل.

تحقّق من عمله: يكتسب الشريط الجانبي صفّ **تحميل ملف** أسفل **مهام الأتمتة**
مباشرةً، وتعرض الصفحة المجلد الرئيسي للمضيف، ويستقر التحميل المنتهي في المجلد الذي
اخترته:

```bash
ls -l "/the/folder/you/chose"
```

## الإعدادات

يعيش كلا المِقبضين في `config` الخاص بصفّ الإضافة، لذا تحتفظ بهما طبقة التصحيح
في الملف الشخصي عبر الترقيات:

```yaml
- id: file-upload-panel
  name: '@dsh-plugins/file-upload'
  config:
    maxFileBytes: 1048576      # افتراضي 1073741824 (1 GiB), 1024 … 16 GiB
    conflict: overwrite        # افتراضي "rename"
```

| الحقل | الافتراضي | المعنى |
| --- | --- | --- |
| `maxFileBytes` | `1073741824` | الحد الأعلى لملف واحد، والقيمة نفسها مقبولة؛ يُرفض أي جسم أكبر بـ `413` ولا يُخزَّن شيء |
| `conflict` | `"rename"` | معنى أن يكون الاسم محتلًّا: `rename` يُبقي الملف الموجود ويضع الجديد باسم `name (1).ext`؛ و`overwrite` يستبدله |

يعلن الصفّ مخططه كمخطط Standard Schema مكتوب يدويًا، لذا تُتحقَّق القيم أعلاه عند
تنشيط الإضافة، ويُفشِل أي قيمة سيئة الصفّ بخطأ. ولا يقرأ Plugin Manager سوى مخططات
Schemastery الأصلية، لذا يُبلّغ نموذج الإعداد في Plugin Manager عن مخطط هذا الصفّ بأنه غير مدعوم
ولا يعرض أي حقول: عيِّن القيم في التصحيح كما هو مبيَّن أعلاه.

## ملاحظات أمنية

- المسار **مسار دقيق على حاجز Connection عند `/api`**، وليس مسار خادم ويب خامًا، لذا يتطلب كوكي الجلسة الموقَّع من المتصفح ولا يخدم إلا الـ Peer المالك.
  كما لا يضيف من عنده أي تخفيف على مستوى Host/Origin.
- يكتب المسار حيثما يشير إليه المشغّل الموثَّق، بصلاحيات عملية DSH — أي بالمدى
  نفسه الذي يملكه منتقي مجلد مساحة العمل وأداة `bash` أصلًا. يجب أن يكون المجلد
  الوجهة موجودًا مسبقًا؛ فالإضافة لا تنشئ مجلدات.
- يسمّي المتصفح مجلدًا واسم ملف، لا مسارًا داخل أحدهما أبدًا: فالاسم خالٍ من `.`
  وخالٍ من أي فاصل، لذا لا يمكن لطلب أن يفلت من المجلد المختار.
- تُنشأ الملفات المؤقتة بجوار هدفها وتُزال عند الفشل أو الإلغاء؛ ولا يبقى شيء تحت
  الاسم النهائي ما لم يصل كل بايت.

## قيود معروفة

- قائمة تحميل واحدة لكل زيارة للصفحة: فالقائمة محليّة في الصفحة، ومغادرة الصفحة
  أثناء التحميل تُبقي النقل جاريًا (المضيف يُكمل الملف) لكنها تنسى الصفوف.
- لا إنشاء مجلدات في المنتقي ولا استئناف: فالتحميل الفاشل يبدأ من البايت الأول.
- يعرض المنتقي المجلدات فقط، والمستويات المقطوعة تُبلّغ `truncated` بدلًا من الترقيم.
- لا تملك الصفحة فحصًا مسبقًا في العميل لـ `maxFileBytes`: فالمضيف يرفض الملف
  الأكبر حجمًا بعد النقل.
- يكتب المضيف نص الخطأ بالإنجليزية ويُبقي رمز errno في الرسالة.

## التطوير

```bash
npm test        # node --test: 22 حالة على المسار والحزمة
npm run check   # بوابة نحوية على كلا النصفين
```

تشغّل اختبارات المضيف المسار عبر كائنات `Request`/`Response` حقيقية ومجلد مؤقت
حقيقي، لذا تغطي مسار البايتات، وسياسات التعارض، وسقف الحجم، والإلغاء، ونص الفشل
دون harness. وتُنفّذ اختبارات المتصفح الحزمة داخل جهاز ظاهري (VM) مع React وDOM
وهميين، لذا لا تحتاج harness ولا متصفحًا.
