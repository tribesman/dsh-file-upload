# @dsh-plugins/file-upload

**Рядок зі скріпкою під «Завданнями автоматизації»** у бічній панелі
вебінтерфейсу [DSH](https://github.com/deepseek-ai/deepseek-harness) відкриває
сторінку завантаження: виберіть папку на хості так само, як це робить діалог
робочої області, позначте кілька файлів одразу й дивіться, як кожен із них
завантажується зі своєю смугою прогресу.

<img src="../assets/uploaded.png" alt="Сторінка завантаження файлів після того, як три файли успішно завантажилися: у лівій бічній панелі вибрано рядок зі скріпкою, папку призначення задано, а кожен рядок показує зелену смугу й позначку «Завантажено»" width="1200" />

<sub>Назви робочих областей і сесій у бічній панелі розмито.</sub>

## Чому

DSH уміє виносити байти *за межі* робочої області ([`@dsh-plugins/file-download`](https://github.com/tribesman/dsh-file-download))
і готує вкладення браузера для одного запиту, але не було способу покласти кілька
наявних файлів у папку на сервері, не відкриваючи оболонку на хості. Цей плагін
додає бракувану дію — на те саме місце, де живуть інші глобальні панелі.

## Де це з'являється

| Місце | Що |
| --- | --- |
| Ліва бічна панель | Рядок **«Завантажити файл»** зі значком скріпки, одразу під **«Завданнями автоматизації»** (`order: 11`) |
| Основна колонка | Сторінка завантаження, яка відкривається вибором цього рядка |

<img src="../assets/upload-page.png" alt="Сторінка завантаження файлів, коли папку призначення ще не вибрано: рядок у бічній панелі стоїть під «Завданнями автоматизації», на сторінці видно картку призначення й пунктирну зону перетягування" width="1200" />

Усе на сторінці — один потік:

1. **Папка призначення** — кнопка *Вибрати папку* відкриває вбудований діалог,
   який спирається на власний список каталогів хоста
   (`ctx.uiWorkspace.listDirectory` — той самий примітив, що стоїть за
   **Select Workspace Directory**): переходи навігаційним ланцюжком, шлях, який
   редагується кліком, перемикач прихованих папок і підтвердження
   *Вибрати цю папку*. Список папок надходить із хоста, тому все працює й у
   віддаленому браузері, де немає системного вибору папок.

   <img src="../assets/folder-picker.png" alt="Діалог вибору папки на сервері: навігаційний ланцюжок показує «Домашня папка» і демонстраційну папку, нижче перелічено archive, photos і reports" width="1200" />

2. **Вибір файлів** — засіб вибору файлів на сторінці приймає кілька файлів
   одразу, а файли, перетягнуті в будь-яке місце сторінки, потрапляють до тієї ж
   черги.
3. **Завантаження файлів** — черга йде по одному файлу; у кожному рядку видно
   лічильник надісланих байтів, смугу прогресу й позначку стану. Рядок із
   помилкою зберігає повідомлення й пропонує **Повторити**;
   **Скасувати завантаження** зупиняє чергу й залишає решту рядків готовими.

   <img src="../assets/uploading.png" alt="Завантаження триває: перший рядок показує 215 МБ із 800 МБ, смуга заповнена наполовину й стоїть позначка «Завантажується», інші рядки чекають у стані «Готово до завантаження», а в заголовку пропонується «Скасувати завантаження»" width="1200" />

## Як це працює

**Серверна частина** — один автентифікований потоковий маршрут на спільній межі
`/api`:

```
POST /api/file-upload/write?dir=<absolute folder>&name=<file name>
content-type: application/octet-stream
```

Він спирається на `ctx.connection.fetch`, тому Connection звіряє запит із
підписаними обліковими даними Harness, які надіслав браузер, ще до того, як
спрацює цей обробник: неавтентифікований запит до нього не доходить, а
обслуговується лише Peer-власник. Обидві координати перевіряються (абсолютний наявний каталог; одне
«голе» ім'я файлу без роздільників), а тіло записується одразу в сусідній файл
`.dsh-upload-<uuid>.part`, який перейменовується на місце лише після того, як
надійшов останній байт: перерване або невдале завантаження не лишає нічого під
справжнім ім'ям.

**Браузерна частина** — написаний вручну лінивий CJS-bundle, якому потрібен лише
базовий набір, заздалегідь наданий оболонкою (`react`, `react-dom`). Він
реєструє два елементи: рядок `sidebar.panellist` і панель `main` з тим самим
ключем — і більше нічого бічній панелі для вибору не потрібно. Саме
звичайний `XMLHttpRequest` у потоці сторінки робить прогрес для кожного файлу
справжнім: `xhr.upload.onprogress` повідомляє про байти, які браузер справді
віддав у сокет.

## Встановлення

Пакет — це **bundle** (`dsh.bundle.patch`), тому Plugin Manager може встановити
й оновити його одним рядком:

```bash
# з локальної копії — додає цей каталог посиланням, зміни діють одразу
dsh plugin --profile web add /path/to/dsh-file-upload

# або з git-репозиторію
dsh plugin --profile web add "git+https://github.com/tribesman/dsh-file-upload.git"
```

Будь-який зі шляхів можна пройти і через інтерфейс: **Плагіни → Додати плагін**.

Якщо `dsh` немає в `PATH`, додайте каталог із копією до профілю символічним
посиланням і впишіть рядок вручну:

```yaml
# $DSH_HOME/profiles/web/cordis.patch.yml
- insert:
    - id: file-upload-panel
      name: '@dsh-plugins/file-upload'
```

```bash
ln -s /path/to/dsh-file-upload \
  "$DSH_HOME/profiles/web/node_modules/@dsh-plugins/file-upload"
```

Ідентифікатор рядка не повинен повторювати той, що вже постачається: `file-upload`
уже належить `@deepseek-ai/dsh-client-file-upload` — транспорту вкладень, які
браузер додає до запиту, — а з двох записів Loader з однаковим id компонується лише
один. Звідси й `file-upload-panel`.

Перезапустіть harness один раз, щоб новий рядок Loader скомпонувався. У вже
запущеному екземплярі вставлений рядок монтується без перезапуску.

Перевірте, що все працює: у бічній панелі з'являється **«Завантажити файл»**
одразу під **«Завданнями автоматизації»**, сторінка показує домашню папку хоста,
а завершене завантаження потрапляє до вибраної вами папки:

```bash
ls -l "/the/folder/you/chose"
```

## Налаштування

Обидва параметри живуть у `config` рядка плагіна, тому шар patch профілю
зберігає їх під час оновлень:

```yaml
- id: file-upload-panel
  name: '@dsh-plugins/file-upload'
  config:
    maxFileBytes: 1048576      # типово 1073741824 (1 GiB), 1024 … 16 GiB
    conflict: overwrite        # типово "rename"
```

| Поле | Типово | Значення |
| --- | --- | --- |
| `maxFileBytes` | `1073741824` | Верхня межа розміру одного файлу: файл рівно такого розміру ще приймається, а більший відхиляється з `413`, і нічого не зберігається |
| `conflict` | `"rename"` | Що означає зайняте ім'я: `rename` зберігає наявний файл і кладе новий поруч як `name (1).ext`; `overwrite` замінює його |

Рядок оголошує свою схему як написану вручну Standard Schema, тому наведені вище
значення перевіряються під час активації плагіна, а через погане значення рядок
падає з помилкою. Plugin Manager читає лише рідні графи Schemastery, тому його
форма налаштування позначає схему цього рядка як непідтримувану й не пропонує
жодного поля: задавайте значення в patch-файлі, як показано вище.

## Зауваження щодо безпеки

- Маршрут — це **точний маршрут на межі Connection `/api`**, а не шлях
  звичайного вебсервера, тому він вимагає підписаного сесійного cookie браузера й
  обслуговує лише Peer-власника. Жодного власного послаблення Host/Origin він не
  додає.
- Маршрут пише туди, куди його спрямує автентифікований оператор, з правами
  процесу DSH — саме ті можливості вже мають вибір каталогу робочої області та
  інструмент `bash`. Папка призначення має вже існувати; плагін не створює папок.
- Браузер називає папку та ім'я файлу, але ніколи — шлях усередині неї: ім'я не
  містить ні крапки, ні роздільників, тому запит не може вийти за межі вибраної
  папки.
- Тимчасові файли створюються поруч із цільовим файлом і видаляються в разі помилки
  чи скасування; під остаточним ім'ям нічого не лишається, доки не надійшов
  кожен байт.

## Відомі обмеження

- Одна черга завантаження на одне відвідання сторінки: список живе на сторінці, і
  вихід зі сторінки посеред завантаження не зупиняє передавання (хост дописує
  файл), але рядки забуваються.
- У діалозі вибору немає створення папок і докачування: невдале завантаження
  починається з першого байта.
- Діалог показує лише папки, а обрізані рівні повідомляють `truncated`
  замість посторінкового виводу.
- На сторінці немає клієнтської попередньої перевірки `maxFileBytes`: завеликий
  файл відхиляє хост після передавання.
- Хост пише текст помилки англійською і зберігає код errno в повідомленні.

## Розробка

```bash
npm test        # node --test: 22 випадки для маршруту та bundle
npm run check   # перевірка синтаксису обох половин
```

Тести серверної частини проганяють маршрут через справжні об'єкти
`Request`/`Response` і справжній тимчасовий каталог, тому покривають байтовий
шлях, політики конфліктів, обмеження розміру, скасування й текст помилки — без
harness. Браузерні тести виконують bundle у віртуальній машині зі заглушками
React і DOM, тому їм не потрібні ні harness, ні браузер.
