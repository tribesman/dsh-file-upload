# @dsh-plugins/file-upload

**Строка со скрепкой под «Задачами автоматизации»** в боковой панели
веб-интерфейса [DSH](https://github.com/deepseek-ai/deepseek-harness) открывает
страницу загрузки: выберите папку на хосте так же, как это делает диалог
рабочей области, отметьте сразу несколько файлов и следите, как каждый из них
загружается со своей полосой прогресса.

## Зачем

DSH умеет выносить байты *за пределы* рабочей области ([`@dsh-plugins/file-download`](https://github.com/tribesman/dsh-file-download))
и готовит вложения браузера для одного запроса, но не было способа положить
несколько готовых файлов в папку на сервере, не открывая оболочку на хосте.
Этот плагин добавляет недостающее действие — туда же, где живут остальные
глобальные панели.

## Где это появляется

| Место | Что |
| --- | --- |
| Левая боковая панель | Строка **«Загрузить файл»** с иконкой скрепки, сразу под **«Задачами автоматизации»** (`order: 11`) |
| Основная колонка | Страница загрузки, которая открывается выбором этой строки |

<img src="../assets/upload-page.png" alt="Страница загрузки файлов, пока папка назначения не выбрана: строка в боковой панели стоит под «Задачами автоматизации», на странице видны карточка назначения и пунктирная зона перетаскивания" width="1200" />

Всё на странице — один поток:

1. **Папка назначения** — кнопка *Выбрать папку* открывает встроенный диалог,
   который опирается на собственный список каталогов хоста
   (`ctx.uiWorkspace.listDirectory` — тот же примитив, что стоит за
   **Select Workspace Directory**): переходы по навигационной цепочке, путь,
   который правится щелчком, переключатель скрытых папок и подтверждение
   *Выбрать эту папку*. Список папок приходит с хоста, поэтому всё работает и в
   удалённом браузере, где нет системного выбора папок.

   <img src="../assets/folder-picker.png" alt="Диалог выбора папки на сервере: навигационная цепочка показывает «Домашняя папка» и демонстрационную папку, ниже перечислены archive, photos и reports" width="1200" />

2. **Выбор файлов** — средство выбора на странице принимает сразу несколько
   файлов, а файлы, перетащенные в любое место страницы, попадают в ту же
   очередь.
3. **Загрузка файлов** — очередь идёт по одному файлу; в каждой строке видны
   счётчик отправленных байт, полоса прогресса и метка состояния. Неудачная
   строка сохраняет сообщение и предлагает **Повторить**; **Отменить загрузку**
   останавливает очередь и оставляет оставшиеся строки готовыми.

   <img src="../assets/uploading.png" alt="Идёт загрузка: первая строка сообщает 215 МБ из 800 МБ, полоса заполнена наполовину и стоит метка «Загружается», остальные строки ждут в состоянии «Готов к загрузке», а в заголовке предлагается «Отменить загрузку»" width="1200" />

## Как это работает

**Серверная часть** — один аутентифицированный потоковый маршрут на общей
границе `/api`:

```
POST /api/file-upload/write?dir=<absolute folder>&name=<file name>
content-type: application/octet-stream
```

Он опирается на `ctx.connection.fetch`, поэтому Connection проверяет запрос по
подписанным учётным данным Harness из браузера ещё до того, как сработает этот
обработчик: неаутентифицированный запрос до него не доходит, а обслуживается
только Peer-владелец. Обе координаты проверяются (абсолютный существующий
каталог; одно «голое» имя файла без разделителей), а тело пишется сразу в
соседний файл `.dsh-upload-<uuid>.part`, который переименовывается на место
только после того, как пришёл последний байт, — прерванная или неудачная
загрузка ничего не оставляет под настоящим именем.

**Браузерная часть** — написанный вручную ленивый CJS-bundle, которому нужен
только базовый набор, заранее предоставленный оболочкой (`react`, `react-dom`).
Он регистрирует два элемента: строку `sidebar.panellist` и панель `main` с тем
же ключом — этим исчерпывается весь контракт, который нужен боковой панели.
Именно обычный `XMLHttpRequest` в потоке страницы делает прогресс по каждому
файлу настоящим: `xhr.upload.onprogress` сообщает о байтах, которые браузер
действительно отдал в сокет.

## Установка

Пакет — это **bundle** (`dsh.bundle.patch`), поэтому Plugin Manager может
установить и обновить его как одну строку:

```bash
# из локальной копии — связывает этот каталог, правки применяются сразу
dsh plugin --profile web add /path/to/dsh-file-upload

# или из git-репозитория
dsh plugin --profile web add "git+https://github.com/tribesman/dsh-file-upload.git"
```

Любой из путей можно пройти и через интерфейс: **Плагины → Добавить плагин**.

Если `dsh` нет в `PATH`, добавьте каталог с копией в профиль символической
ссылкой и впишите строку вручную:

```yaml
# $DSH_HOME/profiles/web/cordis.patch.yml
- insert:
    - id: file-upload-panel
      name: '@dsh-plugins/file-upload'
```

```bash
ln -s /path/to/dsh-file-upload \
  "$DSH_HOME/profiles/web/node_modules/@dsh-plugins/file-upload"
```

Идентификатор строки не должен совпадать с уже поставляемым: `file-upload` уже
принадлежит `@deepseek-ai/dsh-client-file-upload` — транспорту вложений, которые
браузер прикладывает к запросу, — а из двух записей Loader с одинаковым id
собирается только одна. Отсюда и `file-upload-panel`.

Перезапустите harness один раз, чтобы вновь добавленная строка Loader
скомпоновалась. В уже запущенном экземпляре вставленная строка монтируется без
перезапуска.

Проверьте, что всё работает: в боковой панели появляется **«Загрузить файл»**
сразу под **«Задачами автоматизации»**, страница показывает домашнюю папку
хоста, а завершённая загрузка попадает в выбранную вами папку:

```bash
ls -l "/the/folder/you/chose"
```

## Настройка

Оба параметра живут в `config` строки плагина, поэтому слой patch профиля
сохраняет их при обновлениях:

```yaml
- id: file-upload-panel
  name: '@dsh-plugins/file-upload'
  config:
    maxFileBytes: 1048576      # по умолчанию 1073741824 (1 GiB), 1024 … 16 GiB
    conflict: overwrite        # по умолчанию "rename"
```

| Поле | По умолчанию | Значение |
| --- | --- | --- |
| `maxFileBytes` | `1073741824` | Верхняя граница размера одного файла: файл ровно такого размера ещё принимается, а тело большего размера отклоняется с `413`, и ничего не сохраняется |
| `conflict` | `"rename"` | Что означает занятое имя: `rename` сохраняет существующий файл и кладёт новый рядом как `name (1).ext`; `overwrite` заменяет его |

Строка объявляет свою схему как написанную вручную Standard Schema, поэтому
значения выше проверяются при активации плагина, а из-за неудачного значения
строка падает с ошибкой. Plugin Manager читает только родные графы Schemastery,
поэтому его форма настройки помечает схему этой строки как неподдерживаемую и не
предлагает полей: задавайте значения в patch-файле, как показано выше.

## Замечания по безопасности

- Маршрут — это **точный маршрут на границе Connection `/api`**, а не путь
  обычного веб-сервера, поэтому он требует подписанной сессионной cookie браузера
  и обслуживает только Peer-владельца. Собственных послаблений Host/Origin он не
  добавляет.
- Маршрут пишет туда, куда его направит аутентифицированный оператор, с правами
  процесса DSH — те же возможности уже есть у выбора каталога рабочей области и
  инструмента `bash`. Папка назначения должна существовать; плагин не создаёт
  папок.
- Браузер называет папку и имя файла, но никогда — путь внутри неё: имя не
  содержит ни точки, ни разделителей, поэтому запрос не может выйти за пределы
  выбранной папки.
- Временные файлы создаются рядом с целевым файлом и удаляются при ошибке или
  отмене; под окончательным именем ничего не остаётся, пока не пришёл каждый
  байт.

## Известные ограничения

- Одна очередь загрузки на одно посещение страницы: список живёт на странице, и
  уход со страницы посреди загрузки не останавливает передачу (хост дописывает
  файл), но строки забываются.
- В диалоге выбора нельзя создать папку, и докачки нет: неудачная загрузка
  начинается с первого байта.
- Диалог показывает только папки, а усечённые уровни сообщают `truncated` вместо
  постраничного вывода.
- На странице нет клиентской проверки `maxFileBytes`: слишком большой файл
  отклоняет хост после передачи.
- Хост пишет текст ошибки на английском и оставляет код errno в сообщении.

## Разработка

```bash
npm test        # node --test: 22 случая по маршруту и bundle
npm run check   # проверка синтаксиса обеих половин
```

Тесты серверной части прогоняют маршрут через настоящие объекты
`Request`/`Response` и настоящий временный каталог, поэтому покрывают байтовый
путь, политики конфликтов, ограничение размера, отмену и текст ошибки — без
harness. Браузерные тесты исполняют bundle в виртуальной машине с заглушками
React и DOM, поэтому им не нужны ни harness, ни браузер.
